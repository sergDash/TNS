# Схемы и перечни

Здесь две вещи: машинно-проверяемая схема настроек и база перечней
допустимых значений.

## Правила

- Схема описывает форму данных, которую можно проверить. Сейчас она одна:
  `httpapi.schema.json` — настройки приложения `config/httpapi.json`.
- Перечни допустимых значений (жанры, строи, режимы походов, рейтинги,
  языки, сословия, варианты появления героя) лежат в `enums.db`. Таблицы
  мира начинаются с `world_`, героя — с `hero_`; колонка `ord` задаёт
  порядок.
- `config/` хранит только выбранное: включённые языки и умолчания героя.
  Загрузчик проверяет выбор по `enums.db`; расхождение останавливает запуск
  с именем значения.
- Валидатора JSON Schema нет: схему настроек читает движок, перечни —
  модуль мира. Схема и загрузчик правятся в одной правке.
- Добавить значение — правка `enums.db` (через `sqlite3`). Выбрать
  значение — правка `config/httpapi.json`.

## Содержимое

| Файл | Предмет |
|---|---|
| `httpapi.schema.json` | настройки приложения `config/httpapi.json` |
| `enums.db` | перечни допустимых значений и поля формы героя |

## Таблицы `enums.db`

| Таблица | Значения |
|---|---|
| `world_genres` | 30 жанров |
| `world_social_orders` | 18 строёв |
| `world_travel_modes` | 3 режима походов |
| `world_ratings` | 3 рейтинга |
| `world_langs` | 7 языков |
| `hero_estates` | 6 сословий |
| `hero_arrivals` | 4 варианта появления |
| `hero_fields` | поля формы героя: подпись, подсказка, обязательность, предел, ссылка на перечень вариантов |

У таблиц перечней две колонки: `value` и `ord`. У `hero_fields` — `id`,
`title`, `hint`, `required`, `max_length`, `options_table`, `ord`.
