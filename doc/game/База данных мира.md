# База данных мира

Статус: черновик, состав уточняется. Сверено с кодом: 2026-11-28.

## Решение

Одна база на мир: `worlds/<адрес>/world.db`. Это файл SQLite; таблицы ниже —
его схема. В базе факты игры, заготовки и книга. Перечни допустимых значений
(жанры, строи, сословия, рейтинги, языки) лежат в `schemas/enums.db`.

## Что в базе

| Слой | Таблицы (черновик) | Что хранит | Статус |
|---|---|---|---|
| Мир | `world_meta` | анкета, ответы героя, время рождения, настройки мира ключами | заменить `worlds` |
| Герой | `character_layers` | слой `state`: восемь статов и настроение | заменить `hero` |
| Ход | `sessions`, `turns` | сессия и обмены «реплика — ответ» | следующий шаг |
| Сцена | `scenes`, `scene_arc`, `scene_signals` | сцена, её арка, сигналы напряжения | позже |
| Книга | `book_chapters`, `book_text`, `book_cuts`, `book_claim`, `book_peaks` | главы, текст, правки, заявка, пики | позже |
| Труппа | `characters`, `character_state`, `memory_topics` | карточки NPC, положение, память | позже |
| Карта | `places`, `paths`, `rings`, `corridors`, `player_map` | места, пути, кольца, известное | позже |
| Подготовка | `bank_pool`, `lit_template`, `sediment_scene`, `horoscope_issue`, `wakeups` | заготовки, формы, осевшее, гороскоп, утренний пакет | позже |
| Векторы | `vectors` | BLOB float32 1024 с владельцем и исходным текстом | позже |
| Журнал | `events` | доменные события мира | позже |
| Профиль | `player_atlas` | психотип, темы, привычки | позже |

Правая колонка — не решение, а инвентарь: что вообще придётся хранить.
Состав группы уточняется, когда до неё доходит очередь.

## Первый шаг: мир и герой

### `world_meta`

```sql
world_meta("key" TEXT PRIMARY KEY, value TEXT NOT NULL)
```

Мир один на файл, поэтому адрес (`slug`) здесь не дублируется: адрес — имя
каталога.

Значение — обычный текст. Где нужен перечень или структура, в `value`
кладётся JSON-текст: так хранятся `genres` (массив строк) и `hero.answers`
(объект с ответами формы).

| Ключ | Что это |
|---|---|
| `title` | название мира |
| `synopsis` | заявка: одно-три предложения |
| `lang` | язык мира |
| `travel_mode` | режим походов |
| `genres` | JSON-массив жанров |
| `social_order` | строй |
| `censorship` | рейтинг |
| `created_at` | время рождения, RFC 3339 |
| `hero.answers` | ответы формы героя одной строкой JSON |

Список ключей согласован 2026-11-28.

### `character_layers`

Герой — персонаж с номером ноль, как в старой версии. Его телесное
состояние лежит слоем:

```sql
character_layers(character_id INTEGER NOT NULL, layer TEXT NOT NULL,
                 payload_json TEXT NOT NULL)
```

Слой `state` — восемь статов 0–100 и настроение. Навыки и параметры памяти
добавятся в тот же JSON, когда появятся механики, которые их меняют:
слой расширяется без правки схемы.

## Следующий шаг: ход

`sessions` — глава-сессия: когда началась, когда закрылась.
`turns` — одна строка на обмен: `player_text`, `reply_text`, `path`,
`latency_ms`, `created_at`, ссылка на сессию. Поля для решений и доверия
добавятся вместе с механизмами, которые их заполняют.

Вопрос: открывать сессию при рождении мира или при первом ходе. От этого
зависит, что делать с миром, в который ещё не играли.

## Где что лежит

- перечни допустимых значений — в `schemas/enums.db`;
- очередь и сроки — в `engine/jobs` (работа с `NotBefore`) и `engine/events`
  (повторяющийся срок);
- журнал работы — в файлах журнала;
- веса моделей — в `models/`;
- выбор открытого мира — в `config/active_world.json`.

## Открытые вопросы

1. Получает ли герой строку в `characters` с номером ноль, когда появится
   труппа, или остаётся только со слоями и ответами.
2. Книга: таблицы или файлы в папке мира.
3. Настройки мира: ключи `world_meta` или `config/`.
