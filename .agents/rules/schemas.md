# Канон в схеме, в конфиге — выбранное

Вопрос «где держать перечни и настройки» решён один раз и действует на весь
проект. Его не нужно задавать заново и не нужно решать по-разному в разных
модулях.

## Правило

- **Канонические перечни живут в схемах.** Жанры, строи, рейтинги, языки,
  сословия, варианты появления героя и прочие допустимые значения лежат в
  `schemas/*.schema.json`, в разделе `$defs`, через `enum`. Это контракт:
  что игра признаёт законным.
- **Конфиг хранит только выбранное.** В `config/*.json` — какие языки
  включены, чем заполнены поля, какие пути и значения взяты у этого
  экземпляра. Списков допустимых значений в конфиге нет.
- **Форму данных описывает схема.** Поля, подписи, подсказки, пределы,
  обязательность и порядок полей берутся из схемы; порядок свойств в
  документе значим и сохраняется загрузчиком.
- **Валидатора JSON Schema нет.** Ни в образце, ни здесь, пока не понадобится
  проверять произвольные документы обмена. Схему читает загрузчик модуля:
  ему нужны перечни и форма, а не проверка. Поэтому библиотека не
  подключается.
- **Расхождение ловится при запуске.** Умолчание вне списка, язык вне канона,
  неизвестное поле — ошибка с именем значения, а не тихое опускание.
- **Добавить значение в канон — правка схемы. Выбрать значение — правка
  конфига.** Пересборка не нужна ни там, ни там.
- **Схема и загрузчик правятся одной правкой.** Два описания одной формы не
  должны отставать друг от друга.

## Как это выглядит

`schemas/world.schema.json` держит канон мира (жанры, строи, режимы карт,
рейтинги, языки, сословия, варианты появления героя) и форму ответов героя
(`$defs.heroAnswers`). `config/world.json` содержит только выбранное:

```json
{
  "langs": ["ru"],
  "hero": {"defaults": {"estate": "крестьянин", "arrival": "очнулся в чужом теле"}}
}
```

Настройки модуля указывают на оба файла: `schema` и `config`.

## Проверка

Спросите: если это значение игра признаёт законным — оно в схеме. Если это
выбор этого экземпляра — оно в конфиге. Если значение есть в обоих местах
или списки продублированы — одно из них лишнее.
