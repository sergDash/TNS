# Перечни — в базе, выбранное — в конфиге

Вопрос «где держать перечни и настройки» решён один раз и действует на весь
проект. Его не нужно задавать заново и не нужно решать по-разному в разных
модулях.

## Правило

- **Перечни допустимых значений живут в `schemas/enums.db`.** Жанры, строи,
  режимы походов, рейтинги, языки, сословия и варианты появления героя —
  таблицы `world_*` и `hero_*` с колонками `value` и `ord`. Это то, что игра
  признаёт законным.
- **Форма героя описана там же.** Таблица `hero_fields`: подпись, подсказка,
  обязательность, предел, ссылка на перечень вариантов и порядок.
- **Конфиг хранит только выбранное.** В `config/httpapi.json`, раздел
  `modules.settings.world` — включённые языки и умолчания героя. Списков
  допустимых значений в конфиге нет.
- **Схемы остаются для формы данных.** `schemas/httpapi.schema.json`
  описывает настройки приложения; перечни игры в схемах не лежат.
- **Расхождение ловится при запуске.** Умолчание вне перечня, язык вне
  списка, неизвестное поле — ошибка с именем значения, а не тихое опускание.
- **Добавить значение — правка `enums.db`. Выбрать значение — правка
  конфига.** Пересборка не нужна ни там, ни там.
- **Загрузчик и база правятся одной правкой.** Два описания одной формы не
  должны отставать друг от друга.

## Как это выглядит

`schemas/enums.db` держит таблицы `world_genres`, `world_social_orders`,
`world_travel_modes`, `world_ratings`, `world_langs`, `hero_estates`,
`hero_arrivals` и `hero_fields`. Раздел `modules.settings.world` в
`config/httpapi.json` содержит только выбранное:

```json
{
  "enums": "schemas/enums.db",
  "langs": ["ru"],
  "heroDefaults": {"estate": "крестьянин", "arrival": "очнулся в чужом теле"}
}
```

## Проверка

Спросите: если это значение игра признаёт законным — оно в `enums.db`.
Если это выбор этого экземпляра — оно в конфиге. Если значение есть в обоих
местах или списки продублированы — одно из них лишнее.
