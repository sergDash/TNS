# TNS на go-wex: задание на переезд

Этот файл — задание, а не описание текущего состояния. Оно отвечает на три
вопроса: что остаётся от TNS, какими механизмами это выражается после переезда
и как проверить, что игровые идеи не потерялись по дороге.

Основания лежат рядом: `Как распутать.md` разбирает устройство TNS по коду
и переводит его словарь, `Переезд.md` фиксирует решения о переносе. Этот файл
превращает оба разбора в работу: термины, примитивы go-wex, перечень идей
с проверками и порядок шагов. Если разбор и задание расходятся — прав разбор,
а задание исправляется в той же правке.

Что ещё не решено и где стоят заглушки — в `Открытые вопросы.md`. Решение по
открытому вопросу записывается туда же, а не в переписку: иначе следующий
читатель не отличит принятое от временного.

Данные и настройки разделены так: канонические перечни (жанры, строи,
сословия, рейтинги, языки) живут в схемах `schemas/`, а `config/` хранит
только выбранное для этого экземпляра. Правило — `.agents/rules/schemas.md`,
устройство — `schemas/AGENTS.md`.

## Итог

TNS остаётся тем же продуктом: игрок пишет реплику, мир отвечает текстом,
переписка складывается в книгу, а тяжёлое готовится заранее. Меняется
устройство: собственный движок TNS заменяется движком go-wex, а всё, что
относится к игре, остаётся в модулях TNS.

**Контуров ровно два, и это единственное деление, которое нужно.**

- **Контур хода** — синхронный: реплика игрока, ответ нужен сейчас, работа
  идёт в обработчике запроса и укладывается в бюджет задержки. В очередь
  она не попадает.
- **Контур фона** — очередь: работа, результат которой понадобится позже.
  Переживает перезапуск, повторяется после ошибки, выполняется в простое
  и не раньше своего срока.

Всё остальное — не контуры, а ресурсы и службы: слот генерации (модель
отвечает по одному запросу), дочерние процессы станка, книга, карта, банки.
Третьего контура не вводится; если для новой нужды хочется третий, это
признак, что нужда выражается сроком или порогом простоя, а не новым
механизмом.

Три правила важнее остальных, и они действуют на каждом шаге.

1. **Слово вводится под сущность данных.** Если два слова описывают одно
   поле — это одно слово. Если одно слово отвечает на два разных вопроса —
   это два слова. Проверка простая: покажите постороннему структуру данных
   и спросите, что происходит с каждой строкой. Если он рисует поток без
   словаря — описание удалось.
2. **Общепринятое слово не запрещается.** `queue`, `job`, `timeout` — это
   бесплатная документация: читатель уже знает, что они значат. Запрет
   на «выдуманные слова» из `GLOSSARY.md` в части кода отменяется этим
   заданием; роли остаются там, где они создают атмосферу.
3. **Идея не считается перенесённой, пока её нельзя проверить.** Для каждой
   идеи из раздела «Идеи, которые обязаны сохраниться» есть проверка:
   тест, сценарий или действие в интерфейсе. Переезд не заканчивается, пока
   хоть одна строка в этих таблицах без проверки.

## Границы переезда

**Переезжает в go-wex как механизм:** сборка приложения и жизненный цикл
служб, регистрация маршрутов, очередь работ, отложенные сроки, журнал, часы,
подкоманды, настройки, версия сборки.

**Остаётся в TNS как предметная область:** рождение мира, ход и его стадии,
мастерская как набор видов работ, книга и глава, труппа, карта, банки
и заготовки, векторы, цензор, редактор, лемматизатор, модели и их надзор,
языковой пакет.

**Удаляется:** перечислено в разделе «Что удаляется». Удаление — часть
переезда, а не уборка после него: пока старый механизм жив, новый не станет
единственным путём.

**Не входит в задание:** переписывание игровых правил, смена продукта,
новые игровые механики. Если при переносе обнаруживается, что идея держалась
на удаляемом механизме, идея переносится на примитив, а не отменяется.

## Словарь

Первая колонка — слово TNS, вторая — то, чем оно становится в коде и
документации. Третья объясняет, что это в данных, чтобы перевод не остался
переименованием.

| Было | Стало | Что это в данных |
|---|---|---|
| живой ход | контур хода | обработчик запроса без очереди |
| мастерская | контур фона | очередь работ и разборщик |
| заказ | работа (`Job`) | строка очереди: вид, тело, класс, срок, попытки |
| рой | разовый дочерний процесс | запуск с аргументами и рукопожатием версии |
| резидент | служба процесса | долгоживущий ребёнок: модель, эмбеддинги, лемматизатор |
| ядро-надзиратель | точка сборки и группа служб | запуск, лечение и остановка детей |
| станок | машина | слово для людей, не для кода |
| пауза (молчание игрока) | простой | время с последней активности |
| ступень (сколько молчания) | порог простоя (`MinIdle`) | поле вида работы |
| ступень заказа (`light/heavy`) | — | не переносится: тяжесть выражена видом |
| ночь | срок (`NotBefore`) | вычисляется при постановке, когда закрыта глава |
| слот генерации | слот (`gate`) | разрешение семафора, одно на процесс |
| приоритет | срок (`NotBefore`) | поле строки; порядок по сроку, затем по номеру |
| отложенное событие | работа со сроком | строка очереди с `NotBefore` |
| расписание | — | не переносится: порог у вида, пауза у разборщика |
| событие (журнал) | запись журнала | строка журнала |
| событие (мир) | доменное событие | данные модуля, источник состояния |
| ткач | вызов модели | `Generate`: запрос за слотом |
| челнок | выборка из заготовок | `Lookup`: поиск готовой фразы без модели |
| банк | корпус заготовок | таблица готовых фраз и шаблонов |
| форма | шаблон сценария | ситуация, намерение, конфликт, функция |
| заготовка | предгенерированный материал | текст, ожидающий применения |
| пачка | стартовый набор персонажей | 96 карточек-психотипов |
| пила | эвристическая оценка | число «насколько момент напряжён» |
| селектор | правило выбора | политика: заготовка или модель |
| стоп-кран | барьер записи | проверка до фиксации |
| цензор | фильтр содержимого | списки запрещённых лемм |
| редактор | постобработка | правки «было → стало» |
| лемматизатор | морфологический анализатор | словарная форма слова |
| языковой пакет | пакет локализации | словари, лексиконы и тексты промптов |
| вектор смысла | эмбеддинг | точка в смысловом пространстве |
| якорь, синопсис | сюжетная арка, план | ограничение сверху для книги |
| гороскоп | предсказанные ветки | спекулятивная предгенерация |
| карта игрока | профиль игрока | психотип, привычки, интересы |
| труппа | состояние NPC | актёры с отложенной тайной |
| эстафета | цепочка эскалации | передача давления следующему |
| ружьё | реестр предзнаменований | всё показанное подлежит использованию |
| оседание | переработка в заготовки | очистка, дедупликация, оценка |
| вести | отложенные известия | известия дальнего круга |

**Правила перевода.**

- Роли (Ткач, Челнок, Селектор, Пила, Паганель, Пифия, Гефест, Авто-критик,
  Летописец, Картограф, Штурман) остаются в текстах для игрока и в интерфейсе,
  если создают атмосферу. В именах пакетов, функций, полей и в архитектурных
  описаниях стоят слова из второй колонки.
- Слово, у которого два значения, разделяется, а не уточняется в скобках.
  «Ступень» — главный пример: после переезда его нет ни в одном смысле.
- Новый термин вводится только вместе с сущностью данных, которую он
  называет. Синонимы запрещены: одно поле — одно имя во всём проекте, включая
  JSON, тесты и документацию.
- `GLOSSARY.md` переписывается после переезда: в нём остаются роли для игрока
  и объяснение слов, а технические соответствия берутся из этого задания
  и из документации движка.

## Контуры и примитивы движка

Таблица отвечает на вопрос «чем это делается после переезда». Слева — идея
TNS, справа — примитив go-wex, которым она выражается. Примитивы уже есть;
новых механизмов под переезд не придумывается. Движок лежит рядом,
в `~/src/go-wex`; устройство описано в `doc/coding/engine.md`, у каждого
пакета есть свой `AGENTS.md`.

| Идея TNS | Примитив go-wex |
|---|---|
| живой ход | `core.Handler`: обработчик запроса; долгий ответ — `core.HTTPRaw` |
| слот генерации | `gate.New(n)` в точке сборки, переданный и ходу, и обработчику работы; для одной модели `n = 1` |
| мастерская | `jobs.Queue` и `jobs.Dispatcher`: постановка и разбор |
| заказ | `jobs.Request{Kind, Payload, Class, NotBefore, Key}` |
| ступень | `jobs.Spec.MinIdle` плюс `NotBefore`, вычисленный при постановке |
| приоритет | порядок захвата по `NotBefore`, при равенстве — по номеру |
| отложенное событие | работа с `NotBefore`; для повторяющихся сроков — `engine/events` |
| пауза, ночь | `LastActive`, `Touch`, `MinIdle`, `NotBefore` |
| надзиратель | `service.Group` с `SetRestart`, `States`, `Ready` |
| резидент | служба с `Done` и `Ready` |
| рой | запуск дочернего процесса с аргументами и рукопожатием версии; из очереди ребёнок работы не берёт |
| порог времени на ковку | `jobs.Spec.Timeout` |
| остановка без сирот | `service.Group` и `process.Service`: мягкий сигнал, затем срок |
| поток ответа | `core.HTTPRaw`: модуль пишет порции сам |
| три базы TNS | модуль хранилища TNS; движок даёт интерфейсы, а не файл |
| подкоманды | `Registry.Command` с настоящими зависимостями из настроек |
| настройки TNS | `modules.settings.<имя>`: раздел модуля, строгий разбор |
| версия | `engine/version`, подстановка при сборке |
| журнал | `journal.Writer`; шина обновлений интерфейса — служба модуля на сыром маршруте |

Правило, которое нельзя нарушать при переезде: **постановка только ставит,
исполняет только разборщик.** Если результат нужен в ответе — это контур хода,
а не фоновая работа.

## Идеи, которые обязаны сохраниться

Ниже — то, что придумал автор. Каждая строка — идея, её суть в данных и
проверка, по которой видно, что она уцелела. Проверка пишется в том же шаге,
которым переносится идея.

### Мир и рождение

| Идея | Суть | Проверка после переезда |
|---|---|---|
| Рождение мира | анкета создаёт три базы, пачку, якорь и первые заказы; мир переходит в `ready` | анкета создаёт мир; повторный запуск не дублирует персонажей и заказы |
| Анкета | обязательные поля, ошибки по полям, `code` и список полей | пустое поле даёт 400 с `data.code` и `data.fields` |
| Пачка | 96 карточек: 16 психотипов × 6 сословий, без модели; недостающие доковываются по требованию под арку | две генерации с одним сидом дают один набор; под арку без карточки ставится заказ доковки |
| Синопсис и якорь | синопсис как два конца арки; якорь — ближайший нарратив по косинусу | якорь выбран по вектору синопсиса; дрейф виден по главам |
| Порог смерти | здоровье у нижней границы гарантирует прощание | при пороге сцена прощания наступает всегда |
| Финал и переигровка | меню «принять финал / переиграть / новый мир»; новый мир помнит прошлого героя | выбор финала завершает книгу; новый мир видит след прошлого |
| Эпилог | глава авторства игрока с авторской разметкой пиков | эпилог сохраняется отдельно от ленты и помечает пики |

### Контур хода

| Идея | Суть | Проверка после переезда |
|---|---|---|
| Ход по стадиям | реплика проходит стадии: словарь, векторы, предвыбор, подтверждение, путь, коммит | одна реплика даёт один ответ и одну запись; повтор не дублирует |
| Предвыбор | до подтверждения готовы оба варианта: запись банка и промпт модели | оба варианта существуют до фиксации; в мир до подтверждения не записано |
| Стоп-кран | до подтверждения смысла в мир ничего не пишется | отказ на подтверждении не меняет мир; принятие пишет одной транзакцией |
| Двухголосие подтверждения | словарь главнее вектора; пороги заданы настройкой | расхождение выше порога даёт отказ, ниже — проходит |
| Биндер слотов | токены `[NPC]`, `[PLACE]` закрываются лицами и местами по тегам | после хода в тексте нет открытых токенов; привязка живёт сцену |
| Селектор | правило выбора: барьер, команда, страховка, повторяемое, эмоция, совет, неопределённость | на каждом входе виден выбранный путь и причина |
| Пила | эвристическая оценка напряжения; советует, но не решает | Пила вызывается в ходе; её совет виден рядом с решением Селектора |
| Арка сцены | граница по месту, времени и участникам обнуляет арку | смена места открывает новую сцену и обнуляет арку |
| Лайк и дизлайк | лайк двигает литературные параметры и приоритет оседания; второй дизлайк откатывает ход | лайк меняет параметры; второй дизлайк возвращает сырой ход |
| Стриминговая подкладка | пока модель пишет, игрок читает заготовки; ответ идёт порциями | первая порция приходит раньше последней; подкладка видна отдельно |
| Факты отдельно от инструкций | промпт = факты мира + инструкция эмоции | смена эмоции не меняет факты в промпте |

### Контур фона и предгенерация

| Идея | Суть | Проверка после переезда |
|---|---|---|
| Пробуждение | заранее сваренный утренний пакет: последние ходы, статы, портрет, положение | пакет готов до возврата игрока; «к утру» не берётся раньше срока |
| Гороскоп | выпуск под сцену: ветки ответа, прогноз напряжения, темы ковки; перековывается по смене темы | выпуск существует до сцены; совпадение ранних векторов отдаёт готовую ветку без генерации; промах не форсируется |
| Пифия | долгий профиль игрока из лайков, реплик и тем | профиль обновляется по ходам и виден в данных |
| Оседание | удачная сцена проходит очистку, дедупликацию и оценку и попадает в банк | заказ оседания исполняется; сцена попадает в банк с уровнем доверия |
| Переплавка осевшего | осевшая сцена переплавляется в форму со слотами и поднимается до проверенного доверия | после оседания появляется форма со слотами; доверие записи поднято |
| План ковки по релевантности пути | в простое куётся нужное текущему пути: цель — вечер, утро или завтра; суточная норма 2–5 заготовок; дальняя ставится только при свободной очереди, ненужная снимается до исполнения | за сутки заготовок не больше нормы; смена пути снимает дальние; снятая до исполнения не исполняется |
| Вектор судьбы | NPC вне орбиты двигается по сроку; коммит событиями | NPC меняет положение без игрока; события отложенные |
| Вести | запаздывающие известия дальнего круга; на возврате — сводка | после отсутствия приходит сводка и вести; при необходимости сцена |
| Удача мира | параметр, влияющий на вероятностные события | при одном сиде и разных параметрах исходы различаются |
| Слот генерации | модель отвечает по одному запросу; ход и фон не одновременно | два одновременных обращения дают одного держателя слота |

### Книга и глава

| Идея | Суть | Проверка после переезда |
|---|---|---|
| Глава и сессия | глава — лог сессии; сон закрывает главу, автозакрытие через 20 ч | сон закрывает главу; долгий простой закрывает её сам |
| Книга игрока | публикуемая версия глав, правки игрока, отдельный текст | опубликованное отдельно от ленты; правка помечена автором |

### Мир и карта

| Идея | Суть | Проверка после переезда |
|---|---|---|
| Труппа | NPC рождаются без истории, помнят встречи, приходят и уходят по решению движка | NPC помнит встречу; появление и уход видны в сцене |
| Ружьё | всё показанное регистрируется; выбор ищет незаряженное | показанное попадает в реестр; выбор предлагает именно его |
| Отложенная тайна | тайна назначается позже и переосмысляет показанное | новая тайна ссылается на показанное ранее |
| Паганель | земля достраивается кольцами и коридорами; режимы картографа | кольцо строится по порогу; коридор ведёт; места появляются на карте |
| Карта игрока и вьюпорт | известные места и положение героя | вьюпорт показывает только известное; отметка места пишется в ходе |

### Материалы и смысл

| Идея | Суть | Проверка после переезда |
|---|---|---|
| Банки | рутина, драма, страховка; выбор по тегам сцены | рутина выдаётся без дрейфа; страховка спасает пустой выбор |
| Формы | ситуация, намерение, конфликт, функция | форма выбирается по тегам, слоты закрываются |
| Вектор смысла | эмбеддинг 1024: интент, настроение, пробел лексикона, анти-повтор, память, релевантность | все шесть применений работают на одном формате вектора |
| Дедупликация | косинусный порог, а не совпадение строк | близкий по смыслу текст не попадает в банк дважды |
| Память NPC | темы с весом и полураспадом | вес темы падает со временем и растёт при повторе |
| Лемматизатор | морфологическая форма слова | лемма одна для словоформ; язык — параметр, а не константа |
| Архетипная сетка | сцена выбирается по архетипу, внутри — вариации под психотип | разные психотипы получают разные вариации одной сцены |
| Промпты в пакете | тексты промптов лежат в файле языкового пакета с манифестом и запасным вариантом в коде; правка роли главнее файла | правка файла доезжает до запроса без пересборки; пропавший файл не ломает запрос |
| Параметры запроса | температура, предел токенов, `top_p`/`top_k`, бюджет рассуждений, тайм-аут и повторы доходят до тела запроса; незаданное поле не отправляется | правка настройки меняет тело запроса; незаданное поле в запросе отсутствует, и работает умолчание модели |

### Данные

| Идея | Суть | Проверка после переезда |
|---|---|---|
| Три базы | `base` только на чтение, `literary` пишет подготовка, `world` — игра | запись не тем писателем отвергается |
| Карта писателей | таблица «таблица → писатель» и хэндлы только на чтение | нарушение карты ловится в момент записи |
| Миграции | версия, повтор, отказ при файле новее кода | повторный запуск не мигрирует дважды; новый файл отвергается |
| Векторы в BLOB | float32, размерность 1024 | формат сохранён: якорь, дедуп и карта читают старые векторы; длинный чанк книги тоже получает вектор |
| Версия и рукопожатие | версия сборки в рукопожатии дочернего процесса | родитель и ребёнок видят одну версию |

## Что удаляется

Удаление идёт вместе с переносом, а не после. Механизм, оставленный «на
всякий случай», сохраняет второй путь и возвращает путаницу.

- **Шкала приоритетов по видам** (`KindPriority`, `ORDER BY priority`).
  Порядок задаёт срок; запоздавший результат не должен обгонять более ранний.
- **Глобальная ступень паузы** (`PauseNone…Night`, переходы, журнал переходов,
  `SetChapterClosed`, событие смены ступени). Порог объявляет вид работы,
  состояние главы превращается в срок при постановке.
- **Колонка `step` у заказа** и признак «вид пишет прозу» (`KindHasProse`).
  Тяжесть выражена видом; что можно на простое — решает порог.
- **`resumable` и `checkpoint_json`**. Одна работа — один короткий шаг;
  продолжение — следующая работа со сроком, состояние живёт в базе мира.
- **Второй путь исполнения**: вызов модели из постановки (`Enqueue → attempt`).
  Постановка только ставит.
- **Дедупликация через `COUNT(*)` по виду**. Ключ уникальности среди живых
  работ.
- **`deferred_events` как отдельная сущность.** Разовый срок — работа со
  сроком; повторяющийся — событие движка.
- **Пять механизмов часов.** Одни часы и данные: момент последней активности,
  срок работы, срок события.
- **Глобальные переменные процесса** (`DefaultScheduler`, `curSlot`,
  `curSched`, `WorkshopSlots`) и `findEngineRoot()`. Зависимости приходят
  аргументами из точки сборки.
- **Ручная сборка `cmd/tns65`** переключателем по подкомандам. Модули
  объявляют возможности, точка сборки их собирает.
- **Конверт ответа как единственная форма.** Модуль может назвать данные
  ошибки; поток и скачивание идут сырым маршрутом.

## Порядок работ

Каждый шаг заканчивается запуском и проверкой. Проверка формулируется как
наблюдаемое поведение, а не как «собралось». Шаг не начинается, пока
предыдущий не проверен: переезд идёт по одному контуру.

1. **Каркас.** TNS поднимается на go-wex: настройки, модуль состояния,
   статика, журнал, версия. Проверка: страница открывается, процесс
   останавливается без остатков и без сирот.
2. **Контур хода.** Обработчик запроса, стадии, слот генерации, стоп-кран.
   Проверка: реплика получает ответ; при отказе подтверждения мир не меняется;
   два одновременных хода дают одного держателя слота.
3. **Контур фона.** Очередь поверх базы мира: виды работ, срок, порог простоя,
   отмена, ключ, предел попытки. Проверка: три момента времени дают три набора
   допустимых работ; зависшая работа освобождает разборщик по сроку; отмена
   не оставляет работы.
4. **Модели и надзор.** Службы модели, эмбеддингов, лемматизатора: запуск,
   готовность, лечение, остановка. Проверка: убитая модель поднимается,
   готовность видна, первые работы не уходят в отказ на прогреве.
5. **Предгенерация.** Пробуждение, гороскоп, оседание, переплавка осевшего,
   план ковки, векторы судьбы, вести — работы со сроком. Проверка: каждая из
   них исполняется по сроку и оставляет результат в своей таблице; за сутки
   заготовок не больше нормы плана ковки.
6. **Книга и глава.** Глава, книга, заявка, глубокий разбор, редактор, цензор,
   эпилог. Проверка: сон закрывает главу; опубликованное отдельно от ленты;
   ковка книги не падает на запрещённом слове, а гороскоп и справочник эпохи
   проходят словарную проверку до записи.
7. **Мир и карта.** Труппа, ружьё, тайна, Паганель, карта игрока. Проверка:
   показанное попадает в реестр; кольцо строится по порогу; вьюпорт показывает
   только известное.
8. **Поток в интерфейс.** Обновления без опроса через сырой маршрут; порции
   ответа. Проверка: порции приходят по мере готовности; страница обновляется
   без опроса.
9. **Словарь и уборка.** Остатки переименовываются по таблице, код удалённых
   механизмов снимается, `GLOSSARY.md` и `DOCS` переписываются на новые
   термины. Проверка: `grep` по старым словам не находит их в коде и
   документации; все проверки из таблиц идей проходят.

Переименование идёт вместе с переносом, а не отдельным большим шагом: код,
который переносится, получает новые имена в той же правке, а код, который
удаляется, не переименовывается вовсе. Отдельным шагом остаётся только
уборка остатков.

## Опасные места

Это места, где идея держалась на удаляемом механизме или вообще не была
подключена. Их нельзя переносить «как получится».

- **«Ход приоритетнее ковки».** Счётчик хода в TNS не увеличивался, поэтому
  свойство существовало только на бумаге. После переезда: ход берёт слот,
  фон ждёт; проверка — одновременные обращения дают одного держателя.
- **Пила и Селектор.** Пила советует, Селектор решает; в текущей сборке Пила
  не вызывается. При переезде она подключается к ходу, иначе разделение
  «совет/решение» исчезает молча.
- **Оседание, гороскоп, Пифия, заявка книги, глубокий разбор.** Конвейеры
  существуют, но в живом пути не вызываются. Перенос без вызова оставит
  идеи в виде библиотек: у каждой должен быть вид работы или стадия хода.
- **Отложенные события в двух местах.** Доставка на возврате игрока и таймер
  мастерской — одна идея в двух реализациях. После переезда остаётся работа
  со сроком, а «на возврате» — это срок, вычисленный при постановке.
- **Ружьё и тайна.** Это события и слои персонажа, а не отдельные сущности.
  При переносе данные переезжают миграцией, а не переписываются заново.
- **Три базы и карта писателей.** Это дисциплина, которая ловит ошибки
  в момент записи. Хранилище движка — не замена: базы TNS остаются в модуле.
- **Цензор при ковке книг.** Строка «цензор режет всё до записи» неверна:
  15.11.2026 решением владельца (IMP-13) цензор из ковки книг убран, потому
  что запрещённое слово («тварь», «дурак») возвращало ошибку наверх и роняло
  книгу целиком. Цензор остаётся на оседании, гороскопе, справочнике эпохи,
  кольце земли и на правках Редактора; ковка книги идёт без него.
- **Векторы.** Формат (float32, 1024) — часть данных: якорь, дедупликация
  и карта игрока читают старые векторы.
- **Языковой пакет.** Язык и путь к пакету — параметр модуля, а не константа
  в коде: иначе сменный слой останется обещанием.
- **Идеи без кода.** «Лицо мира», «эстафета», «сопротивление чужому» описаны,
  но не реализованы. В переезд они входят как доменные работы с проверкой,
  а не как готовые пакеты, и не удаляются из-за отсутствия кода.
- **Барьер записи и тело ошибки.** Анкета требует кода и списка полей; ответ
  движка обязан это выражать, иначе «мир объясняет, что не так» пропадёт.

## Правила работы

- Перед правкой кода — перевод по таблице; новое имя без сущности данных
  не вводится. Код, который будет удалён, не переименовывается: его удаляют.
- Один механизм — один путь. Если появился второй, первый удаляется в той же
  правке.
- Документация меняется вместе с кодом; документ, описывающий снятый
  механизм, исправляется, а не остаётся «для истории» (история — в журнале
  и в разборах падений).
- Каждый шаг заканчивается прогоном и проверкой из таблиц идей; проверка
  записывается рядом с идеей.
- Игровая идея не удаляется без отдельного решения, записанного здесь:
  «не переносим, потому что…». Молчаливая потеря идеи — ошибка переезда.

## Когда переезд закончен

Переезд закончен, когда одновременно верно три вещи: старые механизмы удалены
из кода, все проверки из таблиц идей проходят, а документация и словарь
говорят на новых терминах. Пока хоть одна строка в таблицах идей без
проверки, переезд не закончен, даже если приложение запускается.
